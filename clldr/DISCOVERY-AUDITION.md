# CLLDR — discovery audit and listening workflow

Authority: [CODEX-DISCOVERY-BRIEF.md](CODEX-DISCOVERY-BRIEF.md). Inspected `clldr-prototype` at `9b006db`. [STAGE-A-PROPOSAL.md](STAGE-A-PROPOSAL.md) supplies the implementation inventory, not an approved layout, final knob deck or compatibility obligation.

**Evidence boundary:** code inspection and automated signal/UI checks are available. No human listening assessment has been performed or invented here. All musical classifications below start **Untested**. Existing patches are convenient stimuli, not approved sounds. A test proving that a parameter changes samples does not prove it deserves a control.

## 1. Short audit — baseline before this pass

| Code fact                                                                                                                                                           | Listening consequence / gap                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Collision zero does not bypass ring modulation. Unison XOR with matching signs can become constant and then silent through DC removal; that is a mechanism result, not automatically a playback bug. |
| Original FM, receiving-frequency-relative FM and causal PM are mutually exclusive before combination. Collision has a response curve and separate algorithm ranges. | Equal fader percentages are not equal modulation strengths. Compare algorithms separately from depth/range/curve changes. No algorithm is preselected as musically best.                                                                      |

Precise near-unison and repeatable numerical comparisons were awkward.                                                                                                                  |
| AMP is one global ADSR. There is no one-knob “length” contract.                                                                                                                    |
| Clean strike/repeat reset source/envelope/feedback/noise/filter history; legacy Strike/Space retain state.                                                          | Snapshot settings alone do not reproduce engine history. Use clean onsets to compare isolated changes; use Drone separately to study continuous evolution.                                                                                    |
| Repeat uses the audio sample clock and a 55% gate. Melody flag currently means root/+12/−12/+7, clamped to MIDI 24–96.                                              | Percussive testing is available. | A/B snapshots retain full settings and update the active slot on edits; the inactive slot is the reference. | The source/interaction view is pre-envelope, roughly 20 Hz and a bounded 2048-sample window.                                                                        | Visible movement is not evidence of audible output or chaos. Use final-output meters to confirm sound and record telemetry only as numerical evidence.                                                                                        |
| FIR decimation/DC blocking exist, but no musical filter, FILTER ADSR, assignable MOD ADSRs, patchable LFO or modulation matrix exists.                              | Do not depict these as functional. FILTER and MOD work requires a separate decision.                                                                                                                                                          |

Current trace separation follows the fader position as a metaphor, not a measured coupling strength. Range zero can therefore leave sources independent even while their displayed centres converge; waveform deformation still comes from telemetry. Record the actual algorithm, range and depth, not just visual proximity.

The protective DC blocker attenuates very low difference tones (its 0.995 pole is roughly a 38 Hz corner at 48 kHz). Low-note findings must distinguish this engine behaviour from oscillator-tuning merit. Fixed frequency clamps and approximate alias mitigation also limit strong-coupling/high-note comparisons.

### Gate/transport ambiguities — report before replacement

| Existing action | Actual semantics                                                                                       | What the target transport could otherwise lose                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| Legacy Strike   | Phase/sweep retrigger, attack from current envelope level, UI-timed 180 ms note-off unless held/drone. | Continuous-state retrigger and its different attack/feedback history.                                                       |
| Clean strike    | Full reset, sample-clock 180 ms gate unless held/drone.                                                | A fixed-length clean comparison if replaced by a press-duration gate.                                                       |
| Hold            | Runtime latching gate; distinct from the saved Drone setting.                                          | Ability to keep a gate open without selecting a drone configuration.                                                        |
| Drone           | Keeps the gate open, starting if off; sustains at AMP Sustain, not necessarily audible indefinitely.   | Does not imply a fresh reset on every Play. State-continuity policy must be explicit.                                       |
| Repeat          | Repeated clean notes, adjustable rate, 55% gate, resets at each onset.                                 | Not a general sequencer; do not expand it into one.                                                                         |
| Pitch sequence  | Existing `auditionSequence` boolean changes pitches within Repeat.                                     | In the target UI, **Sequence** mode means repeated gates; **Melody** means the four-pitch test. These must not be confused. |
| Space           | Held legacy key gate outside form controls; key-up releases unless held/drone.                         | Keyboard semantics must be stated if changed to clean triggering or Play/Stop.                                              |
| Stop            | Cancels pending/active starts and releases AMP; the release tail remains.                              | Must stay immediate as a command, without waiting for audio resume; it is not a hard mute.                                  |

The user explicitly selected **clean held Trigger: reset on press, release on lift**. The compact lab header now implements that contract, Drone/Sequence segments, Play→Stop, notes/s and Melody. The old controls are retained in a collapsed “Advanced lab: legacy audition controls” section, not silently removed.

New transport semantics are explicit:

- Trigger interrupts current lab playback, clears Hold/Drone, clean-resets on pointer or keyboard press, and releases on lift. Pointer capture handles lifting outside the button; pointer cancellation/focus loss release the gate. Releasing during audio loading cancels the pending note. Space/Enter on the focused Trigger use this clean held behaviour.
- Body Space retains its existing legacy held-gate semantics outside form controls. No keyboard shortcut was quietly repurposed into Play/Stop.
- Sequence means existing repeated clean gates at the chosen notes/s, fixed pitch when Melody is off. Melody enables the existing four-note test. It is not a new sequencer.
- Drone Play opens the Drone gate and sends an existing legacy note-on immediately, even during a previous release: phase/sweep retrigger and attack from current level, retaining loop/filter memory rather than performing a full clean reset. A zero-sustain sound can naturally decay to silence even in Drone; use Trigger when a clean onset is wanted.
- Mode changes stop playback first; pressing Play is required to start the new mode. Play becomes Stop immediately, including while audio is loading; Stop cancels that pending start and allows the configured release tail.
- Main Trigger, Repeat and Drone do not compete for a gate. Legacy latches remain inspectable; Play/Stop also releases them.

The header uses three functional columns at wide widths and stacks them on narrow screens. It groups lab audition, reference/output, and temporary snapshot/JSON tools. These are discovery conveniences, not the ZW performance or saving architecture.

## 2. Lean staged discovery workflow

1. **Prove audition, then learn the base instrument.** Enable audio, Initialise, check Clean strike/Repeat/Drone and final output. Compare Multiply, Switch and XOR at Collision zero, with zero feedback/imperfections/sweeps. Establish how waveform pairings and ratios alone behave.
2. **Discover usable coupling regions.** Hold one source setup fixed; compare algorithms, then each algorithm's depth, then range and curve separately. Repeat at low/middle/high pitches and near/wide ratios. Record useful regions, quiet/stalled regions, abruptness and pitch changes without forcing increasing “chaos”.
3. **Ask which secondary parameters earn complexity.** Test Shape/Bias, phase, detune, offset and sync in isolation, followed by result feedback and imperfections. Only then test interactions with gentle coupling. A parameter can be redundant in one mode and valuable in another.
4. **Review evidence before arranging the deck.** Classify parameters and choose controls based on collected listening notes. The agreed two-bank deck has no fixed count or assigned occupants yet. Future assignable pitch envelopes need their own decision; legacy pitch transients are not deck candidates.

Keep sessions short: a few comparisons from one family, then stop and record. Do not attempt to evaluate all controls, all notes and all algorithms in one pass. Never turn automatic level correction into a substitute for recording dynamics.

### Neutral/reference starting states — lab recipes, not new patches

**R0: uncoupled reference.** Press Initialise. This supplies A3/57, A ratio 1, B ratio 1.5, sine/sine, tracking 1/1, zero detune/offset/phase/Shape/Bias/pitch transients, Multiply, Collision zero, feedback/imperfections zero, Original FM, curve 1 and default ranges. AMP is 8 ms / 600 ms / 0.65 / 700 ms, Output 0.45, trim 0; pitch lock is off. This is a reproducible starting state, not a claim of musical neutrality or preferred sound.

**R1: short-note reference.** From R0, explicitly set AMP Attack 0.002 s, Decay 0.08 s, Sustain 0 and Release 0.04 s. Select Sequence and use Play at 2 notes/s with Melody off. Establish these settings in both snapshots before a one-parameter test. This deliberate multi-setting setup is not itself an isolated parameter comparison.

**R2: continuous reference.** From R0, select Drone and press Play. Keep AMP/Output fixed; do not assume a switched snapshot recreates source history. For history-controlled confirmation, stop Drone and use Clean strike or Repeat. Use passive trim only for one-shot level matching; capture the quieter reference and attenuate the louder comparison.

No new patch format, reference-preset system, persistent evaluation database or CLLDR performance subsystem is introduced. Existing JSON and snapshots remain temporary lab conveniences, with no promise that their format or historical sounds constrain the ZW architecture.

### One-parameter A/B procedure

1. Select Snapshot A, establish R0/R1/R2 and the fixed test conditions. Store A into B.
2. Select B and edit **one** setting, using the numeric value beside its slider when precision matters. Collision accepts exact percentages.
3. Check **Snapshot A ↔ B**. It should report one changed field, or explicitly record an intentionally paired change such as waveform pairing. Expand it to inspect all differences; changes to trim, note, envelope, algorithm, ranges and audition rate are also reported.
4. Switch A/B and compare equally held clean Trigger presses, legacy Clean pulses of fixed length, or the next Sequence onset. For percussive tests keep Melody off initially; use the same press length or fixed-length lab pulse to avoid gate-duration confounds. Use continuous Drone comparisons as a separate, history-dependent test.
5. If matching levels requires passive trim, the difference count will include trim: record that deliberate confound. Equal RMS does not guarantee equal loudness; silence and lost transients are results to log, not to boost away.
6. Return B to the reference value, or store A into B before testing another parameter. This avoids accumulated hidden changes. For pitch-transposition tests change the reference note deliberately and document that both variants are re-established at that note.

Do not mix Drone snapshots into a clean-gate comparison without re-establishing both references: the existing saved `drone` flag can reopen a gate when a snapshot is recalled, and main Trigger deliberately clears it. The difference list reports that change rather than hiding it.

The difference readout compares declared settings, not phase, noise-generator position, filter memory, sequence position or output-tuner correction. Empty or nonfinite numeric edits restore the previous value; finite out-of-range edits use the existing DSP bounds. Exact entry is not quantised to the coarser slider step.

The bare existence of a parameter is no argument for retaining it. A technically nonzero effect can be **Inconsequential** in the intended musical context; an interesting effect can still be **Off-brief**. Conversely, a parameter redundant at one setting may be **Useful** through a distinct interaction.

## 4. Classification and evaluation log

Definitions for human evaluation:

- **Essential:** removing the behaviour undermines CLLDR's demonstrated musical identity or a core playable gesture.
- **Useful:** earns its complexity in identifiable musical contexts; placement still needs evidence.
- **Inconsequential:** no worthwhile distinct contribution in the documented contexts, including comparisons against overlapping controls.
- **Off-brief:** may be audible or attractive but pulls away from the intended ring-modulation instrument or belongs to shared ZW architecture.
- **Untested:** not auditioned, inconclusive, or insufficient evidence. This is the initial state, not a negative judgment.

Ring multiplication is required by the brief independently of listening classification. Code facts and numerical observations go in their own column; only a listener supplies perceptual descriptions and classifications. Include counterexamples before proposing removal.

Use [LISTENING-LOG.md](LISTENING-LOG.md) as a copyable session template. It records source settings, note/gate conditions, exact A/B deltas, coupling units/ranges, intentional trim changes, useful regions, failures and confidence. No permanent CLLDR patch/evaluation system is proposed.

## 6. Agreed direction versus deferred work

The later interface direction is a compact wide-screen header in **three functional columns** (lab audition / mode-reference configuration / temporary comparison-file conveniences), stacking whole functional groups responsively. It is not a CLLDR-specific ZW saving/performance standard.

The main bridge uses symmetric tuning rings/waveform selectors around truthful A/B/interaction telemetry and a central Collision fader with Multiply/Switch/XOR. The two medium-knob banks below it have **no approved control count or assigned candidates yet**. AMP envelopes remain visible by default. Advanced is collapsed, followed by a distinct Chaos rack, then Mod Matrix last. Do not render unimplemented FILTER/MOD/routing panels as functioning features, or invent an LFO to occupy a section. No dropdowns are proposed for the intended instrument; existing lab selects are not a precedent for it.

This pass deliberately does not rebuild that fascia. It gathers evidence first. FILTER topology, the two assignable ENV 3 ADSRs/routing, additional transport semantics beyond this lab contract and any destructive DSP deletion require explicit decisions. No such decision is inferred from the provisional Stage A proposal.

## 7. Verification and next audition

Automated checks establish only their named behaviours: comparison coverage, bounded edits, unchanged DSP fixtures, generated output, repeat timing, sequence notes and responsive lab layout. They do not establish musical quality, a preferred waveform/coupling algorithm or final deck placement.

The Node suite now includes four snapshot-comparison tests covering all 44 fields, runtime-state exclusion and accidental confounds. Browser smoke checks exact fractional values, blank restoration, out-of-range clamping, difference counts and snapshot copying. The playback regression retains its old measured-audio assertions and adds clean held pointer/keyboard Trigger, release outside/focus loss, Sequence 2 Hz attacks, all Melody pitches, Drone Play/Stop, stop-before-mode-change and pending Play/Trigger cancellation. These are generated-signal checks, not physical-device listening assessments.

Run `npm start` from the repository root. Begin with **T01–T05**, using R0 for the sustained comparison and R1 for rhythmic confirmation. Record which uncoupled waveform/ratio interactions actually feel alien, metallic, rhythmic, unruly or otherwise relevant. Only then proceed to Collision and secondary candidates. The next recommendation should be derived from those notes, not from how many controls are already implemented.
